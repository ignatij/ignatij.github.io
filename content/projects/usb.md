## Context & risk

Four separate hospital applications in Basel had diverged in both UI behavior and how each implemented authentication, authorization, and external service integrations. Duplicating security and integration logic across four healthcare codebases increases audit surface area and makes policy changes error-prone.

## Architecture & key tradeoffs

- **Reusable Java/Spring security & integration libraries:** Consolidated common authentication, authorization, and third-party integration mechanics into shared backend libraries rather than copying security plumbing into each application.
- **Shared Angular/PrimeNG component system:** Standardized frontend UI primitives across all four hospital applications to eliminate drift and duplicated maintenance.

## Role & outcome

- Led requirements, estimation, code reviews, and developer coaching while contributing hands-on to both the Java/Spring backend libraries and Angular component system.
- Unified four hospital applications onto shared security, integration, and UI foundations, eliminating duplicated auth and integration code across the suite.
